# Choosing which tests to run

Run commands from the repository root.

## Test diagnostic tools without Docker

Requirements: Bash and Python 3.

```bash
bash scripts/test_tools.sh
```

This command tests JSON log parsing, request ID lookup against saved input,
proxy log summaries and both Markdown renderers.

It uses synthetic data and temporary files. It does not start containers
or send HTTP requests to the application.

Passing these tests validates the diagnostic tools, not the running lab.

## Test the running environment

Start the services first:

```bash
docker compose up -d --build --wait --wait-timeout 60
```

Choose the test according to what you want to verify:

| Command | Purpose | Effect on the environment |
| --- | --- | --- |
| `python3 tests/http_smoke.py` | Check HTTP routes and JSON responses | Sends requests |
| `python3 tests/test_access_logs.py` | Check request IDs and correlated JSON logs | Sends requests and reads logs |
| `python3 tests/test_live_request_lookup.py` | Check lookup against live service logs | Sends a request and reads logs |
| `bash tests/test_shutdown.sh` | Check SIGTERM and SIGINT handling | Creates and removes isolated temporary containers |
| `bash tests/test_recovery.sh` | Check backend outage and recovery | Temporarily stops the lab application |
| `bash tests/test_diagnostics.sh` | Check diagnostic failure detection | Temporarily stops the lab application |
| `bash tests/test_slow_backend.sh` | Check a backend read timeout | Enables the slow scenario and restores the default configuration |

Run disruptive tests sequentially against the local lab. Running them
together can cause one test to change the environment while another is
checking it.

Cleanup handlers attempt restoration, but cannot run after SIGKILL or
host failure. See the [operations guide](operations.md) for recovery.

## Render saved evidence

The renderers accept JSON through stdin or a file path.
They format existing measurements; they do not query the application.

Files such as `slow-backend-summary.json` are generated by CI and included
in its diagnostics artifact. They do not appear locally after a Git pull.

Download and extract the artifact on the machine where you will run the
renderer, then supply the actual path to the extracted JSON file.

See the [logging guide](logging.md) for interpreting the reports.
